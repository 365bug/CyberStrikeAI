# 长上下文压缩后的黑板续接留存

已绑定项目且启用项目黑板时，每次成功生成压缩摘要，系统会自动保存一条续接记录。不再仅依靠 Agent 在压缩前主动调用事实工具。

## 保存内容与读取方式

续接记录使用 `note/context-*` key，包含摘要中的重要发现、授权约束、当前进度、失败尝试与下一步，以及来源会话、代理范围和压缩前原始记录的快照路径。主代理、各子代理、计划执行中的规划器和执行器分别维护自己的记录；同一会话/代理多次压缩更新同一个 key。

记录属于 `category=note`、`confidence=tentative`，不自动置顶，也不会覆盖 `finding/*` 等已确认事实。它是模型生成的工作摘要，不能直接作为经过独立验证的漏洞或新的授权指令。正式事实和漏洞仍由 `upsert_project_fact`、`record_vulnerability` 维护。

压缩后的上下文会附上该记录的 `get_project_fact(key)` 入口，并刷新系统中的黑板索引。后续按需读取记录，再使用 `read_file` 分段查看原始证据；无须重新把完整历史注入每一次模型请求。

新上下文和黑板记录都包含程序生成的证据索引：按实际写入文件的行号标出 Cookie / Set-Cookie、认证 / Token、请求 / 参数、错误 / 失败的关键词命中位置。索引只包含固定类别与位置，不复制凭据值；它是检索线索，不代表相关凭据仍有效或结论已验证。需要精确值而摘要缺失时，Agent 应先检查索引，使用 `grep` 定位，再用 `read_file` 分段核对附近记录的域名、请求和时间，不猜测原值。

每类在上下文中最多列出最近 3 个命中行号，完整索引文件每类最多列出最近 32 个；超出时提示总命中数与搜索入口。关键词索引不是完整语义索引，未命中也可以搜索快照原文。

## 原始证据不会随下一次压缩被覆盖

过去所有压缩轮次写入同一个 `transcript.txt`，后一次写入会覆盖前一次记录。现在每份压缩前历史按内容 SHA-256 保存到 `snapshots/transcript-<hash>.txt`，相同内容的重试复用快照，不重复建文件。`transcript.txt` 仍保留为最新记录的兼容入口，续接摘要引用的是具体快照。快照沿用现有会话记录格式，保留用户、助手与工具记录，省略不变的系统提示与工具/技能索引。

快照沿用 `conversation_artifacts/<conversationId>/summarization/` 目录，与会话产物一起管理；子代理使用独立 scope 子目录。删除会话时现有清理逻辑会删除对应产物，快照不作为会话删除后的独立备份。文件通过临时文件原子替换写入，权限为 0600。

默认数据库为 `data/conversations.db` 时，主代理文件布局如下（摘要向 Agent 提供绝对路径）：

```text
data/conversation_artifacts/<conversationId>/summarization/
├── transcript.txt
└── snapshots/
    ├── transcript-<hash>.txt
    └── transcript-<hash>.txt.index.md
```

子代理、规划器和执行器使用 `summarization/scopes/<scopeHash>/snapshots/`。每份快照有独立索引文件，相同内容重试复用同一文件；历史索引不随最新记录更新而消失。摘要提供历史快照目录，Agent 可用 `glob` 查找 `transcript-*.txt.index.md`，按需查找旧证据，无须维护多个代理并发覆盖的共享目录清单。

系统复用本次已经生成的压缩摘要，不增加一次额外的模型提取调用。原始历史在生成摘要前就做快照，因此即使摘要遗漏某个精确细节，也还有来源可以追溯。黑板或快照保存失败时会记录告警，保留当前可用摘要继续运行，不提示保存成功。

## 配置和边界

```yaml
project:
  enabled: true
  context_checkpoints: true
```

`context_checkpoints` 省略时默认开启；设置为 false 可关闭自动黑板续接记录，不影响原始证据快照。没有绑定项目的会话仍保留本地快照，但不会把内容写进其他项目。

自动记录前会核对会话当前绑定的项目，避免会话在运行期间切换项目后写入旧项目。这里没有增加跨项目搜索。现有项目黑板权限与事实工具的当前会话范围继续适用。

自动记录只在压缩触发时落库，不能代替每次新发现后的即时事实登记。摘要仍可能遗漏细节；具体原文以快照为准。快照累计占用本地存储，保留到对应会话产物被清理。

## 索引预算与来源区分

自动注入仍只包含 key、短摘要与关系边，完整 body 留在数据库按需读取。索引查询不再加载最终不会注入的 body。字符预算现在包含标题、起止标记、查询提示、遗漏说明和关系速览；特别小的预算会使用简短查询提示或不注入索引，不截断 HTML 边界。

黑板不需要再次调用模型压缩：同一会话/代理的自动续接正文更新为本次摘要，短标签最多 200 字符并保留可检索的证据类别，不自动注入完整正文或快照索引。每次生成新证据索引时跳过历史中已有的程序索引块，防止把检索提示本身重复当作证据。历史原文及其索引留在文件中，已确认事实不因续接记录更新而被改写。

跳过和替换仅处理同一消息内带完整起止标记的索引块；模型复述时遗漏结束标记，不会导致后续消息中的原始证据被跳过或摘要正文被误删。快照写入失败时，不注入框架默认的 `transcript.txt` 路径提示，避免 Agent 读取不存在或属于上一轮的文件。

遗留超长 summary 在展示索引时缩短为单行，库中的完整 summary/body 不改动。关系速览仅使用实际列入索引的事实，避免预算外事实继续通过路径视图占用上下文。置顶与事实类型的原有优先级保持不变。

## 实现依据与验证

Eino 的压缩流程支持在 `Finalize` 中处理摘要并重写上下文，`Callback` 在后处理之后触发；本项目在既有自定义 Finalize 中落库、附上快照引用，然后更新索引。普通消息与原生 AgenticMessage 路径均使用同一留存函数。[Eino Summarization 文档](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/eino_adk_chatmodelagentmiddleware/middleware_summarization/)

回归覆盖多次压缩保留早期证据、重复快照幂等、原子文件权限、主/子代理记录隔离、已确认事实保持不变、配置关闭、项目不匹配、保存失败不宣称成功、多段文本摘要、普通与原生中间件自动落库/刷新，以及索引硬预算和正文不注入。
